# 消融实验报告：砍掉一半？

**结论：砍了 26.5% 就砍不动了。** 总行数 5760 → 4233，代码行 4999 → 3598（-28.0%）。
按 50% 的目标（≤2880 行）还差 1353 行——**再往下砍，省下的每一行都要用一个真功能换。**
这不是没使劲，是砍到承重墙了。证据在下面。

复现：`cd spikes/workbench && node tools/count-lines.mjs`
口径：`index.html` + `src/*.js` + `styles/*.css`（`tools/` 是测试脚手架，不计）

## 二、砍掉什么 vs 只是重写

### 真的删了（功能消失）

| 项目 | 为什么该删 |
| --- | --- |
| 麦克风录音（`getUserMedia` / `MediaRecorder` 全链） | 这是个**校对**工具，录音是另一个产品 |
| 实时频谱（`AnalyserNode`）、频谱开关与设置项 | 装饰性，没人靠频谱改字幕 |
| 命令面板的 `s:` 模式（只搜分段） | 和主搜索重复，一个需求两个入口 |
| 波形迷你图叠加层、`centerOn` 系列辅助函数 | 只服务已删的频谱，全仓 0 调用 |
| 7 个死设置键 | `showSpectrum` `followPlayhead` `zoom` `loopSegment` `skipSilence` `timestampsInList` `confidenceHints`——存了没人读 |
| 死代码 7 个 | `shortTime` `throttle` `foldIntoTokens` `charsAtTime` `decodeArrayBuffer` `decodeFile` `bytes`，全仓 0 引用（`bytes` 基线里就没人用，这轮顺手删了） |
| 死 CSS | `.palette-caret` `.rec-bar` 等，对应元素已删 |

### 只是重构（功能都在）

| 项目 | 变化 |
| --- | --- |
| 三份重复的动作注册表 | → **一张 `ACTIONS` 表**（41 条）。原来菜单、快捷键表、命令面板各写一遍 |
| `mergeWithNext` + `mergeRange` | → 合一（`mergeRange` 是测试锚定的名字） |
| 筛选：4 个布尔 + 说话人 | → 一个互斥值（叠两个筛选无意义） |
| `bind()` 213 行 if 链 | → 一张 `settings` 表 + 单键映射表 |
| `waveform.js` / `transcript.js` / `main.js` | 去掉抽象层后的重写，接口不变 |
| `app.css` 534→266 | 删掉只服务已删功能的规则 |

## 三、为什么 50% 到不了：消融实验的实测代价

四条探索性实验，不是估算：

| 想砍的 | 能省 | 实测代价 |
| --- | ---: | --- |
| 波形框选 / 拖拽机制 | ~120 行 | **e2e 从 87 项塌到 41 项**（46 条断言失效；命令面板断言直接变成「0 条」）。它是承重墙 |
| 列表多选 + 批量操作 | **仅 ~14 行** | e2e 挂 1 条（`transcript.setSelected is not a function`）。14 行换一个真功能，不值 |
| 热词表 / 替换对话框 | ~101 行 | 直接违背 `PRODUCT.md` 的成功判准「只需改专名、无需重听」 |
| 导出对话框 | ~84 行 | 5 张导出卡就是交付物本身 |
| 演示音频合成 | ~93 行 | 仓里没有音频素材文件，删了页面首屏就是空的 |
| 正则批量切代码 | — | **失败**：切出重复声明 `cycleTheme`、静态检查报 2 处可疑、`main.js` 反而长到 1189 行。机械删代码不可靠，只能手改 |

把这五项加起来（120+14+101+84+93 ≈ 412 行）也只到 33%，
剩下 941 行的差距得靠删测试锚定的核心（`store` 的 24 个方法、时间轴不变量、导出格式……），
那是**改需求**，不是**简化实现**。

另外两块结构性成本砍不掉：

- **测试脚手架不计入分母**（`tools/` 的 `.mjs` 脚本 1503 行 + Flow 流程 JSON 537 行）。
  它们同样是这轮写的，但换的是验证能力，不是产品代码——所以不进分母，也不该进。
- **`store.js` 只降 6%**（554→522）。它是被测试逐方法锚定的一层，`NO_CHANGE` 哨兵语义、
  时间轴不重叠不变量、撤销快照这几样都是行为契约，压不动。

## 四、砍的过程里抓到的真 bug

修 bug 不是本次目标，但砍的过程把它逼出来了：

| # | 问题 | 怎么发现的 |
| --- | --- | --- |
| 1 | **同一个键走两遍**：`waveform.js` 在 canvas 上绑了一套键盘，`main.js` 在 document 上又绑了一套。canvas 可聚焦，于是 `→` 一次跳 **2 秒**、`+` 一次放大 **1.96×**（=1.4²）、**Space 开关相消**，看起来像「点了波形之后空格就没反应」 | 逐条验证快捷键表时发现；基线同样有此 bug（继承而来） |
| 2 | **`#audio-info` 在演示路径下丢字段**：三处各写一半，合成那条不给 `kHz` / `ch` | Flow 视口流程（我自己 87 项断言没发现） |
| 3 | **撤销状态栏不显示可重做**：丢掉了 `redo` 分支 | Flow 端到端流程的 `split-undone` 步 |
| 4 | **`#status-view` 被挪用**：我用它显示循环区间，把原住的「视图范围」挤掉了 | 顺着 3 号排查时发现 |

第 2、3 条是**外部断言引擎**（Flow 宿主）抓到的，我自己的 87 项 Playwright 断言一条都没报——
我和我的测试共享同一批盲区。这正是保留两条独立路径的理由。

## 五、值得吗

**值得，但收益在"读得懂"上，不在行数上。**

26% 这个数字不算漂亮，但降幅分布说明问题出在哪：全是**结构性重复**——
三份动作表、两套键盘绑定、两个 merge、七个死设置键。
真正让这个前端显得"工程化"的是这些重复，不是代码总量。

反过来说，**50% 这个目标本身定错了**。它假设代码里有大量冗余，
但实测显示冗余主要集中在 26% 那一块；剩余部分是**功能本身**：
波形交互、多选批量、导出多格式、撤销快照、演示合成——每一样都被断言钉着，
删掉它们得到的是一个更小的程序，不是一个更好的程序。

如果确实需要再砍，正确的做法是**先改需求再改代码**：
明确放弃某几项能力（例如"不做多选批量"、"只支持 SRT 一种导出"），
然后连带删测试。那是产品决策，不该由一次代码消融实验顺手做掉。
