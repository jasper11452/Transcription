# 转录工作台（前端 spike）

一块**音频 + 带时间戳的转录文本**的校对工作面：听、跳、改、导。

这是 `spikes/` 下的独立实验，不接入 `src/transcript/` 的后端，不写用户数据，不参与打包。
零 npm 依赖、零构建、零远程请求（不加载 CDN、远程字体或图标）。

> 这一轮做过一次**消融实验**（目标：砍掉一半代码）：实际砍掉 **26.5%**（5760 → 4233 行），
> 没到 50%，以及为什么到不了、每条再砍的实测代价，都在 **[ABLATION.md](./ABLATION.md)**。
> 顺带抓出 4 个真 bug，其中 2 个是外部断言引擎（Flow）抓到的。

## 为什么单独做一个 spike

`PRODUCT.md` 里把"字幕编辑器"写进了非目标。所以这里不试图改产品范围，
只回答一个上游问题：**给一段录音和一份转录，人到底需要一个什么样的界面才能做到"只需改专名、不用重听"？**
波形怎么用、编辑会不会把时间轴带偏、哪些操作需要撤销——这些在真界面上试一次，比在文档里讨论十次有用。

## 怎么跑

```bash
./serve.sh              # http://127.0.0.1:8899/  （只绑本机回环）
PORT=8900 ./serve.sh    # 换端口
```

打开就有东西：第一次进入会自动合成一段 96 秒的四说话人"会议"音频并载入 13 段转录文本，
不用先准备素材。合成用的是共振峰模型 + 音节包络 + 房间底噪，听得出谁在说话、听得出停顿，
所以波形缩放、跟读高亮、静音跳过、说话人着色都能被真实触发。

要测真实录音：把音频/视频文件拖到页面上，或点「打开」。字幕文件（`.srt` / `.vtt`）和 `raw.json` 也能拖进来。

## 能做什么

**音频与波形**
- 拖拽/选择文件载入；也接受 `.srt` / `.vtt` / `raw.json` 纯文本拖入
- 画布波形：缩放、平移、迷你导航条、点击定位、拖拽框选、双击整段选中
- 播放速度 0.75–2×、音量、循环当前段、循环选区、跳过静音（基于 RMS 预扫的静音区间）
- 按说话人着色的波形色带（可切单色）

**转录校对**
- 点时间码跳播；播放时逐段跟读高亮 + 段落内进度条
- 双击（或 E）就地编辑，`⌘↵` 提交、`Esc` 放弃
- 拆分（S，在播放头处按时间比例切文字）、合并（M）、插入（I）、删除
- 多选后批量合并 / 删除 / 标记 / 复制 / 改说话人
- 置信度标记：低于 72% 标黄，可以一键跳到下一个可疑段
- 待复核标记、搜索（命中高亮 + 只显示命中）、按低置信/待复核/已改/说话人筛选
- 全部操作可撤销，撤销栈 60 步，标签直接写在状态栏上

**整理与产物**
- 批量：合并过短分段、规整时间轴（消除重叠）、查找替换（支持正则）、热词表替换（`错=对`）
- 导出 txt / 带时间戳 txt / 带说话人 txt / srt / vtt / markdown / raw.json，支持复制到剪贴板或下载
- 导出前检查：空段、时间重叠、异常字数密度、过短字幕
- 编辑自动存在本机（localStorage），刷新不丢；有未保存改动时离开会拦一下

**界面**
- ⌘K 命令面板（30+ 条命令，模糊匹配）；`?` 看快捷键全表
- 深浅色主题 + 跟随系统、可调字号、减少动画
- 三栏响应式，窄屏重排；键盘能走完全程
- 失败不吞：解码失败、存储写满、剪贴板不可用都会落进侧栏日志并有可见提示

## 代码结构

```
index.html            外壳与静态骨架（内联 SVG 图标，无远程资源）
serve.sh              起服务
styles/tokens.css     设计变量，深浅两套主题
styles/app.css        组件与响应式
src/util.js           纯函数：时间码、字数、diff、文本清理  ← 无 DOM
src/export.js         五种产物（+两种带时间戳/说话人变体）+ SRT 解析  ← 无 DOM
src/stats.js          统计口径                              ← 无 DOM
src/store.js          状态 + 撤销栈 + 持久化（storage 可注入）
src/audio.js          播放引擎、静音预扫、合成演示音频
src/waveform.js       画布绘制 + 命中测试 + 缩放平移 + 选区
src/transcript.js     分段列表、跟读高亮、搜索、内联编辑
src/palette.js        命令面板与模糊打分
src/ui.js             toast / 模态 / 快捷键表
src/main.js           唯一的装配层：谁认识谁都在这里
tools/serve.js        静态服务（含路径穿越防护）
tools/static-check.mjs 未声明调用与错误导入的静态扫描
tools/test-pure.mjs   纯函数单测
tools/test-store.mjs  store 行为测试（撤销/持久化/时间轴不变量）
tools/e2e-smoke.mjs   真 Chromium 冒烟（87 项断言）
tools/flow-wb-e2e.json / flow-wb-viewports.json  本机 Flow 宿主的端到端流程
tools/run-flow-e2e.sh 一键跑上面两条 Flow 流程
screenshots/          自动化产出的界面截图
```

分层是硬的：`util` / `export` / `stats` 不认识 DOM；`audio` / `waveform` / `transcript` 互不引用，
只通过 `store` 通信，接线全在 `main.js`。所以每一层都能单独在 node 里跑检查。

```bash

node tools/test-pure.mjs          # 纯函数 39 项

./tools/run-flow-e2e.sh           # 用本机 Flow 宿主再跑一遍（两条流程，共 60 步）
```

### 两条互不共享假设的浏览器路径

| 路径 | 驱动 | 作用 |
| --- | --- | --- |
| `tools/e2e-smoke.mjs` | 我自己写的 Playwright 脚本 | 迭代快，断言细节自己控 |
| `tools/flow-wb-e2e.json` + `tools/flow-wb-viewports.json` | 本机 Flow 宿主（`~/flow`）驱动系统 Chrome | **外部驱动、外部断言引擎**，不共享我的假设 |

为什么要两条：这轮 Flow 抓到的问题，我自己那套 87 项断言**一个都没发现**——
因为我和我的测试共享同一批盲区（以为 toast 放在角落没问题、以为 dirty 就该拦刷新）。
`run-flow-e2e.sh` 会先 lint 再跑，两条流程都用生产 `FLOW_HOME`，坑库与 recipe 能沉淀。

Flow 那条会抽取产物（`$FLOW_HOME/runs/<run-id>/product.json`）：从真浏览器 DOM 里取出的
**真实 SRT 文本**，含标准四段时间码，可直接交付——这是"界面里看到的就是能用的东西"的最直接证据。

### 抓到的真问题（留个记录）

这一轮靠断言和截图纸找出来的，都是"看着能跑"但实际错了的：

**渲染与数据**
1. `transcript.js` 的渲染缓存初值写成 `seg.text`，导致正文**永远空白**——第一次绘制就被"已画过"挡掉。
2. `paintText` 的缓存键只有文本、没有搜索词，**搜索高亮永远不出现**。
3. `audio.js` 里跳过静音调用了不存在的 `seek()`，第一帧抛异常就把 `requestAnimationFrame` 掐死，
   表现为**播放头永远不动**（很像音频解码坏了）。现在 tick 内有 try/catch，一帧出错不允许中断整个循环。
4. 语速恒为 **0**：`readSeconds(text, seconds)` 收文本，调用方传的却是数好的字数。
5. `timecode` 分别取整秒和毫秒小数，会写出 `00:59.1000`、`00:60.000` 这类非法时间码。
6. SRT 时间码少了小时段，写出 `00:03,500` 而不是 `00:00:03,500`。
7. `mergeAdjacentShort` 不看时间是否相邻，一次合并会把终点推到下一段的终点上，**造成时间重叠**。
8. `commit` 拿 `false` 当"没改动"的哨兵，与"0 处命中"的正常返回值撞车，两者都错。
9. `replaceDoc` 遇到 `null` 分段条目直接崩（导入的 JSON 不可信，现在会规整）。

**布局与交互（这三条全是 Flow 真浏览器抓到的）**
10. **toast 挡住了可点控件**：`#btn-play` 在左下、toast 也在左下，`elementFromPoint` 命中 toast，点击被拦 25 秒超时。
    实测四个角落在不同视口**都会**压住控件——换位置解决不了。正解是 toast 本体 `pointer-events: none`、
    只留 action/close 可点，让点击穿透。验收判据也从"toast 在哪"改成"关键控件是否真的可点"。
11. **离开拦截过宽**：`dirty` 是全局"动过"标志，切主题这类已自动落盘的动作也置 true，
    于是重新导航触发 `beforeunload`、超时 30 秒。改为按内容指纹判定（`store.unsavedWork`），
    只有磁盘存档与当前转录不一致才拦。真实用户也会被无意义地拦一次——这是产品缺陷，不是测试配置问题。
12. **静默零尺寸**：`.pane-title span { display: none }` 这条通配规则把 `.chip` 一起干掉了，
    1280px 以下 chip 是 0×0。而且 `.pane-tools` 的 `overflow: hidden` 把溢出痕迹也吞了——
    既看不见、也不报错。更早一步我还差点被自己骗过：用"跳过隐藏元素"的脚本查"元素不该隐藏"必然漏报。
13. **单列堆叠时中间面板高度归零**：`grid-template-rows: auto 1fr auto` 在总高不足时把 `1fr` 压成 0，
    侧栏卡片叠到转录面板的列表头上，搜索框被挡住。
14. 标题行被内部控件撑成两行（76px），因为 `.pane-tools` 允许换行而控件总宽超出容器。
15. `.rec-bar { display:flex }` 盖掉 `[hidden]` 的 `display:none`，**录音浮条一直挂在页面上**并挡住点击。
    （该浮条连带整个录音功能已在下面的消融中删除，问题不存在了，但当时的教训保留。）

## 已知边界

- **不做识别。** 这个页面只处理和校对已有转录，不跑 ASR。
- 没有说话人分离，说话人靠人工指定（点芯片循环切换，或批量设置）。
- 长文件解码是同步的一次性开销，只有 toast 提示，没有真实进度条（`decodeAudioData` 不给进度回调）。
- 纯文本导入时时间轴是按段估算的（每段 4 秒），页面会明确警告需要人工对齐。
- 拖入的文本、导入的 JSON 时间轴都当"不可信输入"处理，但仍然只做基本规整。
- 撤销是整份快照：90 分钟的转录 × 60 步大约几十 MB 内存。更大规模需要改成差量。
